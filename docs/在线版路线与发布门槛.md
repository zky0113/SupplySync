# SupplySync 在线版路线与发布门槛

> 历史规划文档：其中的“离线预览”已于 2026-10-10 删除，预测、仿真与 Agent 当前状态以根目录 README 为准。

此文档说明为什么当前目录只能本机访问，以及怎样稳妥地升级成公开在线、可复用的赛题二 B 系统。写于 2026-10-08。这里的“在线”至少有两个不同目标，验收时不能混为一谈。

## 当前事实

- **已有 Web 应用**：`app.py` 是 Streamlit 服务入口；本机用 `启动Demo.cmd` 打开 `http://127.0.0.1:8501`。`127.0.0.1` 只代表运行服务的这台电脑。
- **离线备份已移除**：旧的静态输入预览已删除；完整演示需运行 Streamlit 服务。
- **尚未上线**：没有独立 Git 仓库、云服务项目或公开 HTTPS 地址。此前赛题一的 Cloudflare Pages 项目是另一个纯静态宣传页，不承载这个 Python 系统。
- **当前数据范围**：固定单 SKU 四级模拟网络。输入通过字段、连接、容量、日期、成本、促销和 seed 复现校验。没有声称模拟器与模型已经正确。

## 阶段一：公开在线演示版

目标：任何人打开 HTTPS 链接都能查看当前网络、初始库存与历史需求；在真实计算模块通过验收后逐项开放相应按钮。此阶段使用固定、已校验的合成示例数据。

优先采用 **Streamlit Community Cloud** 托管现有 `app.py`：项目文件进独立 GitHub 仓库，入口设为 `app.py`，依赖由 `requirements.txt` 安装，部署后会得到 `*.streamlit.app` 地址。该路径工作量最少，前端不需要重写。代码已移除配置中的本机固定监听地址，云平台可以按自身设置启动；本机快捷启动脚本仍显式监听 127.0.0.1。部署前排除 `.runtime/`、`.venv/`、日志、密钥和任何未授权数据，只提交经过校验的合成示例数据、源码及必要报告。部署后重新核对网络图、C04 详情、历史图、场景条件和文件下载，并从实际校园网及手机蜂窝网络访问验证。

**Git 注意**：当前桌面目录本身处于另一个 Git 工作区，赛题二 B 文件夹内没有自己的 `.git`。正式发布时应单独初始化本文件夹或将这些文件复制到专用检出目录，并逐项检查待提交文件清单；不要在桌面父目录执行 `git add .`，以免把无关桌面文件一起提交。现有赛题一仓库也不应复用为本赛题后端仓库。

另已准备 `Dockerfile` 和 `.dockerignore`，适合后续需要 Python 容器的平台。容器启动时监听 `0.0.0.0` 和平台提供的 `PORT`，与本机监听地址分开。可在有 Docker 的电脑先运行：

```bash
docker build -t supplysync-demo .
docker run --rm -p 127.0.0.1:8501:8501 supplysync-demo
```

本机未安装 Docker，**容器尚未实际构建与启动验证**。容器配置完成不等于已经部署，也不等于已有公网地址。

Cloudflare Pages 可托管之后独立构建的 HTML/Vue/React 页面，但不能直接运行当前常驻的 Streamlit Python 进程。把离线文件放上 Pages 只能得到静态快照网址，不会变成可上传数据和执行决策的系统。若将来继续使用 Pages，需另有公开 Python API 服务。

**阶段一通过标准**：提供可访问的 HTTPS 地址；外部设备可看四个页面和当前可用图表；相同快照 ID 的数字与本地一致；网页无密钥或个人绝对路径；无假成本/改善值；故障时可使用本地备份演示。公开后将网址、仓库、生产分支、部署方式和更新方法记入 README。

## 阶段二：通用数据与完整决策版

“通用”在赛题二 B 中首先定义为：不同合规供应链数据包，经过同一输入合同与校验流程，能得到对应网络、预测、补货计划和 N 天策略仿真。不是仅把固定 CSV 文件的浏览页面放到公网。

1. **数据合同**：节点、边、SKU、终端历史日需求、初始库存、在途批次、约束、成本、日历和情景分别有版本化 schema。字段约定明确计量单位、日期/时区、必填/可缺省、节点/商品 ID、权限与来源。至少先支持现有四层结构和不同分支规模，再按业务需要扩展多 SKU 与多供应商。
2. **导入与校验**：允许上传或选择合规数据包；先检查文件格式、大小、重复键、时间连续、上下游完整、库存/仓容/成本/提前期合理性；给出错误定位，不直接拿坏数据作图。当前 `demo/provider.py` 用“必须与固定 seed 的生成器逐字节一致”保证示例可信，真实/公开数据必须走独立校验器和来源标记，不能删掉校验后假装通用。
3. **业务计算**：复用共用服务层，对每次输入生成 dataset_id/版本哈希；预测以 as_of 截止，不读未来真值；计划以状态、预测和补货约束计算；仿真以同一初态、需求、成本比较策略；逐项验收守恒、容量、成本和指标准确性。
4. **结果与用户隔离**：每次实验有 run_id、配置、指标和日志；页面切换节点不重算模型。不同用户或数据包不能互相读到未授权输入或结果。真实企业数据需要认证、存储策略和访问控制；正式发布前明确数据权利与使用范围。
5. **Agent**：只通过授权工具读状态/预测/计划/证据；密钥在服务端环境变量。所有数值结论绑定 run_id 和可追溯记录。超时、工具失败或 LLM 不可用时能给出明确状态。
6. **线上工程**：数据和实验结果使用持久化存储，耗时计算改为任务运行与状态查询；配置资源限制与失败重试；监控错误、模型版本和输入版本。前端如需复杂多用户流程，再将 Vue/React 托管在 Pages、Python API 单独部署；近期参赛演示仍可沿用 Streamlit。

**阶段二通过标准**：导入两套结构不同且合法的数据包都能运行全流程；非法数据包被拒并给出具体原因；历史/预测/计划/仿真/Agent 均引用各自 dataset_id 和 run_id；可以独立复算核心指标；不同用户的结果互不泄露。

## 部署选择与访问限制

| 路线 | 适合阶段 | 已知限制 |
|---|---|---|
| Streamlit Community Cloud | 当前 Python 工作台的最快公网展示 | 官方说明闲置应用会休眠，托管位于美国；比赛前需热机，并从国内实际网络测试 |
| Python 容器托管 | 同一工作台继续完善、需要更明确运行环境 | 本项目已备 Dockerfile；仍需选择服务、资源、持久存储与访问控制 |
| Cloudflare Pages + Python API | 后续复杂交互与多用户产品 | 需同时开发和维护静态前端与独立后端；不能直接把 Streamlit 放进 Pages |

学校/国内移动网络是否无需 VPN 稳定访问，必须在**真实上线后**实测；这些海外平台的官方文档不作大陆可达性保证。如果决赛要求现场稳定，准备本地已验备份和录屏。

官方技术资料：[Streamlit Community Cloud 部署](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy)、[应用管理与休眠](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app)、[Cloudflare Pages 静态部署](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/)、[Cloudflare Workers 的 Python 环境](https://developers.cloudflare.com/workers/languages/python/)、[Render FastAPI 部署](https://render.com/docs/deploy-fastapi)。这些是技术资料，不是赛事规则。
